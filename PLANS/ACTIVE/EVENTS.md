# Мероприятия: доступ к записям

## Модель

У каждого видео конференции есть мероприятие («весна 2026», «осень 2026»).
Человек видит и смотрит файл, только если:

1. файл опубликован (`isPublic`);
2. есть ACTIVE `UserEventAccess` именно на это мероприятие;
3. срок доступа по формуле `computeAccessUntil(paymentDate, event.startDate, accessDays)` ещё не истёк.

Staff (MODERATOR / ADMIN / SUPER) видит всё, в том числе скрытое.

`accessUntil` на пользователе остаётся максимумом по всем оплатам — для входа на `/watch-conf` и живой эфир. Список и стрим файла проверяют конкретное мероприятие.

Повторный grant на то же событие обновляет ту же строку (`@@unique([userId, eventId])`).

## Вне скоупа этой итерации

- **Класс** (`ClassFile`) — без `eventId`. Список и стрим класса по-прежнему: опубликовано + любая живая подписка.
- **История оплат** в таблице пользователей — отдельный хвост.

## Реализация

1. Загрузка: обязательный `eventId` (форма `/admin/upload` + upload-service).
2. Список `/conf-arch` и `GET /api/conf-archive/list`: staff — все файлы; остальные — `isPublic` и `eventId` из активных оплат.
3. Стрим `GET /api/conf-archive/[systemName]` и страница `/watch-conf/...`: та же проверка, не глобальный `accessUntil`.
4. Админка: у файла видно мероприятие, можно сменить.
5. Старые файлы без `eventId`: backfill к конференции с ближайшей датой старта (не позже загрузки). В админке можно поправить. Без мероприятия обычный пользователь файл не видит.

## Осталось

3. История оплат в таблице пользователей (кнопка «История», grant/revoke).
